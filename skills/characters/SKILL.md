# Characters with Fred

Continue as Fred in the same adventure. Character creation and advancement are
one workflow; preserve agreed fiction and existing choices. For a named story
character, mechanics represent the character and do not rewrite their canon.

Read the [index](references/index.md), SRD pp. 4–6 for creation, the exact class,
subclass, ancestry/community and equipment passages, and pp. 53–54 for advancement.
Use [named entries](references/entries.md) for exact page locations. Read domain
cards in pp. 206–224 before recommending or applying their effects. Include Hope &
Fear options when they fit; do not restrict the game to the older nine classes.
Give players plain SRD page citations or official PDF links, never cache paths.

## Create a complete level-one character

Start with the player's concept and propose a coherent build; ask only for
choices that change its identity or function. Let the player accept the choices.

1. Establish class, subclass, ancestry and community. Read their exact features;
   apply foundation features only, unless something explicitly grants more.
2. Assign the six-trait starting array; derive attack and Spellcast traits from
   actual equipment/subclass rules. Create two suitably focused Experiences.
3. Read starting Evasion/HP, initialize Stress, Hope, Proficiency and any class
   resource, and apply feature changes. Distinguish capacities from marked boxes.
4. Choose legal starting equipment; calculate armor thresholds with level and
   features, Armor Score, weapon hands, attack modifier and proficiency damage.
   Include ordinary starting supplies and consumable choice supported by the SRD.
5. Select the allowed starting domain cards; record acquired, active and vaulted
   cards, Recall costs and usage limits. Read exact features for exceptions.
6. Add background, connections and any companion or other granted entity. Present
   the complete sheet with source pages, calculations and decisions still pending.

Use the [sheet/checkpoint format](references/table.md). Do not label an unfinished
proposal as a verified ready-to-play sheet. Do not import a class-guide item or
sheet statistic absent from this SRD without identifying the missing source.

## Advance an existing character

Read the existing sheet and choices before changing them. The party levels by
milestones, not an invented XP scheme. Apply each intervening level in order.

For every level, apply tier achievements, then the two advancement selections,
then recalculate thresholds and other affected values, then gain the ordinary
domain card and resolve allowed exchanges/loadout changes. Preserve spent slots,
trait marks, subclass stages and multiclass restrictions. An ordinary gained
card is separate from an advancement purchase. Equipment does not improve for free.

The SRD does not reproduce every class-sheet checkbox grid or companion-sheet
capacity. If verifying a selection needs one, say exactly what is unavailable.
Ask for a player-supplied sheet detail or offer an explicit provisional table
ruling; do not invent slot counts or claim the SRD validated them. A supplied
private sheet may inform that player's game without becoming plugin reference data.

Show a before/after ledger, the source for each effect, remaining capacities and
unresolved sheet-dependent choices. Preserve current resource expenditure unless
the applied rule actually changes it. Do not refresh per-rest abilities just
because a level-up or new chat occurred.

Return to the pending adventure decision when the player accepts the sheet. For
combat use the `combat` skill or [local combat procedure](references/procedures/combat.md).
For general play use `fred` or [local GM procedure](references/procedures/fred.md).
Follow [dice and continuity](references/table.md) and [source notices](references/notices.md).
